# lxm-writing：去 AI 味 + 个人声音

把稿子从「模型腔 / 通稿腔」改成**像作者本人会交出去的中文**。  
目标不是过检测器，也不是变成另一种通用「人类文」。

本 skill 融汇各家做法，并锚定本仓库已有规范。细则出处见同目录 `SOURCES.md`。

---

## 1. 适用范围

**默认用于**：周报、面向老师/合作者的笔记与方法说明、实验叙述。  
**幻灯上屏文案**：走 [`tools/ppt/copy_discipline.md`](../ppt/copy_discipline.md)（压缩语域 + 禁路径/图号；长文规则 §7–§8 仍适用）。  
**可宽松**：README、代码注释（只清明显 chatbot 残留即可）。  
**不要用于**：代码、配置、纯数据表、命令输出。

语域默认按 **formal-research-zh**（克制、有因果、敢写局限）。  
若用户明确说「轻松一点 / 对内草稿」，再下调正式度，但事实纪律不变。

---

## 2. 真相源优先级（冲突时谁赢）

从高到低：

1. **本轮用户硬约束**（「不要改数字」「只改第一段」「保留这句话」）
2. **当场粘贴的本人写作样本**（live sample；见 §4）
3. **`VOICE.md` / `voice-profile.md`**（个人习惯档案；若存在则读取）
4. **项目 `Style.md`**（house style；优先 `nichespate/docs/Style.md`，其次工作区内其他 `Style.md`）
5. **本 skill 的通用规则**（§6–§8）
6. **中性默认**

冲突口诀（多份上游 skill 共识，此处固化）：

> **作者真实习惯 > Style 项目规范 > 通用去 AI 规则 > 中性默认**

Style 管「项目该怎么写」；VOICE / 样本管「这个人平时怎么写」。  
二者分层，不要揉成一份无法维护的大文件。

## 3. 模式

| 模式 | 触发线索 | 做什么 |
|------|----------|--------|
| `rewrite`（默认） | 去 AI 味 / 按我的声音改 / 润色 | 改写并交付 |
| `detect` | 检测 / 审计 / 看看哪里像 AI | 只报告，不改写 |
| `draft` | 按骨架起草周报 | 先吃事实卡片 + Style + VOICE，再写 |
| `voice-update` | 更新 VOICE / 从终稿学习 | 从样本抽取/修订 `VOICE.md`，不改业务正文 |

深度（借鉴 density / light-heavy）：

| 深度 | 何时 | 力度 |
|------|------|------|
| light | 短段落、或用户说「轻改」；AI 痕迹稀疏 | 只动死给的套话与翻译腔 |
| standard | 默认 | 结构优先于换词，完整自检 |
| heavy | 长文、或用户说「深改 / 彻底」；痕迹密集 | 可重排句段，多轮收敛 |

## 4. 声音发现（每次改写前先做）

按顺序尝试，找到即停，并在输出头注明来源：

1. 用户**粘贴了本人样本**，或点了样本文件路径  
2. 工作区存在 `VOICE.md` / `voice-profile.md`（当前目录及向上两级）  
3. 用户说「按 Style 写」但无个人样本 → **仅 Style 模式**（去味 + 项目规范，不强行伪造个性）  
4. 都没有 → **generic 去味**（干净、有方差；不发明人格）

### 4.1 从样本学习什么（贴样本 / 更新 VOICE 时）

从约 ≥150 字的真实文本抽取（样本内容只供节奏，**禁止**把样本里的事实/观点抄进待改稿）：

- 句长分布与是否用短句收束  
- 段落怎么起（问候、回顾、抛问题）  
- 连接词偏好与少用词  
- 标点习惯（句号密度、括号、冒号、破折号）  
- 限定与立场（如何写「尚不确定」「仍有差距」）  
- Avoid：作者明显从不做的事  

`VOICE.md` 建议骨架：

```markdown
# Voice

## Cadence
## Diction
## Signature moves
## Avoid
## Stance
## Sample
（贴一段 80–150 字真文）
```

### 4.2 生成时 vs 改写时

- **改写**：先靠拢声音，再去 tell（voice-first；避免先洗成中性再难加声音）  
- **起草**：规则内建，边写边约束，减少事后缝补造成的风格断层

## 5. 流水线

```
0 判定模式 / 语域 / 深度
1 加载 Style.md + 发现声音（§4）
2 保护区标记（§6）
3 密度预检 → 选 light / standard / heavy
4 Pass A：按声音设定节奏与措辞（有声音时）
5 Pass B：去 AI 味 —— 结构优先于词汇
6 Pass C：自检（可否决前两轮）
7 意义与保护区核对
8 按输出契约交付
```

### Pass B 原则

- **方差优于换词**：均匀句长、均匀段形、同样连接词堆叠，比单个「赋能」更致命  
- **结构先于词汇**：先拆假对照、假三段、假总结，再换词  
- **信息优于外形**：保留全部事实主张；段落可拆可并；不要为了「长得像原文」保留套话壳  
- **空心稿要喊停**：过了禁词检查但没有任何具体数字/路径/结果 → 标 `[HOLLOW]`，请用户补事实，不编造填肉  

### Pass C 自问（强制）

1. 若冷读，还剩哪一两处一眼像模型？  
2. 是否改过了：削掉了真人细节、抹平了作者怪癖、或引入了新的「均匀不规则」？  
3. 是否出现源文没有的事实、因果、数字、路径？  

Pass C 与前两轮冲突时，**Pass C 说了算**。

### Stet

用户说「这句保留 / stet」：本篇不再改该处。  
同一模式被作者三次明确保留 → 提议写入 `VOICE.md` 的 Avoid/Quirks，而不是继续误杀。

## 6. 保护区（不可为「更像人」而改坏）

以下内容默认原样保留，除非用户明确要求改：

- 数字、指标名、实验编号（Exp0–Exp9.1 等）  
- 文件路径、仓库路径、命令、配置键  
- 模型名/方法名的项目标准叫法（以 Style 术语表为准）  
- 引用、图表标题、已冻结文档名  
- 引号内的他文原文  

**禁止编造**：源文没有的机制解释、未给出的提升原因、未提供的引用。  
缺具体时：写短、写朴素，或标 `[需作者补：…]`，不要用假细节换「人味」。

Stance（态度）默认关闭。仅当用户明确要求「带点判断 / 更有锋芒」时，可对**已有事实**加态度，仍不得加新事实。

## 7. 项目 Style 要点（摘要；完整以 Style.md 为准）

改写中文科研 prose 时默认遵守：

- 娓娓道来，诚恳；不夸大胜利或危机；局限可写在相应段落，不必藏到最后  
- 术语首次出现用一句话解释，后文统一叫法，不玩同义词花样  
- 正文默认不加粗；少括号；少用引号强调抽象概念；少用冒号甩长解释  
- 避免「不是 A 而是 B」「与其说…不如说…」「一句话总结」「归根结底」等套话框  
- 避免无数据的「完胜 / 全面更好 / 机制已建立」  
- 周报骨架可参考：问候与主题 → 与上周衔接 → 过程 → 结果表+表下解释 → 目前的认识 → 下一步 → 材料路径  
- 主榜数字须能指回冻结文档或 outputs 路径；探索性不得冒充主榜

## 8. 去 AI 味清单（中文科研优先）

按**簇**判断，不因单点误杀。完整英文 Wikipedia 长表见 `skills-catalog/blader-humanizer.SKILL.md`；此处是高频子集。

### 8.1 中文套话与翻译腔

少用或改写：值得注意的是、综上所述、不难发现、在某种意义上、赋能、闭环、抓手、对齐（非技术义）、落地（空泛义）、打造、助力、降本增效、开启新篇章、提供了有益借鉴。  
少用硬译连接：对于…来说、基于…、围绕…展开、使得…得以…。  
营销拔高：颠覆、革命性、深刻改变、至关重要、不可或缺（无机制时）。

### 8.2 结构腔

- 否定排比 / 假深刻对照：「不是…而是…」「与其说…不如说…」→ 直接说正句（与 Style 一致）  
- 三段式排比堆砌、假范围（「从 A 到 B」两端并不构成谱）  
- 提纲式收束：「挑战与展望」「尽管存在不足，但仍前景广阔」  
- 机械枚举连接：首先/其次/最后/与此同时 连环出现  
- 分词尾巴贴假深度（英文 -ing 分析腔的中文等价：，彰显了…，标志着…，体现了…）  
- 总结段复读全文；结尾拔高到时代命题  

### 8.3 词汇与节奏

- 英文 AI 高频词（delve, tapestry, pivotal, leverage, seamless, robust, underscore, landscape 作比喻等）→ 换成普通词或删  
- 同义词循环称呼同一对象 → 固定用 Style 术语  
- 句长过于均匀 → 拉开长短；但不要做成固定「短-长-短」模板（那是 humanizer 自己的指纹）  
- 聊天残留：好问题！、希望这对你有帮助、作为 AI…、截止我的知识…  

### 8.4 格式腔（与 Style 对齐）

- 正文无故加粗、emoji 标题、**词：解释** 式列表墙  
- 破折号密度过高 → 优先逗号/句号；若 VOICE/样本爱用，则按作者频率保留  
- 表格只放数字对照或步骤；大段解释用段落

## 9. 误报与应保留的人味

**单独出现通常不要当罪证**：完美语法、偶发「然而/因此」、单个破折号、学术用词、一处短句强调。

**看到这些应倾向少改**：难编造的具体细节、混杂情绪与未完成判断、作者可辩护的用语选择、句长真有起伏、自我打断与补充、已经很像既有周报终稿的段落。

过检测器、零宽字符、故意加错别字：**不做**。

## 10. 输出契约

### `rewrite`（粘贴文本时）

```
## 改写稿
Voice: [generic | Style-only | from VOICE.md | matched to pasted sample]
Depth: [light | standard | heavy]

（全文）

## 改了什么
- （最多 6–8 条，按问题类型归并）

## 故意没动
- （1–3 条：看似可疑但像作者本人的地方）

## 意义核对
一句话确认：数字/路径/术语/主张未漂移。若有软性因果推断，点名并收回或加限定。

## 空心标记（如有）
[HOLLOW] …
```

### `detect`

只给问题列表 + 总体评估；不给全文改写。

### `draft`

先确认事实卡片是否够用（做了什么、数字、路径、不确定点）。不够则先问，再写。结构跟 Style 周报骨架。

### `voice-update`

输出更新后的 `VOICE.md` 全文或 diff 说明；征求是否写入文件。注明样本是否偏短（低置信）。

### 文件模式

用户指定文件时：在保护区约束下改文件；对话里只给变更摘要，避免整篇刷屏。

## 11. 推荐调用方式

**贴样本学习（高星工具最常见、也最有效的个人声音用法）**

```text
用 lxm-writing。

这是我本人的写作样本：
（贴 2–3 段已交周报）

请按我的声音去 AI 味改写下面草稿：
（贴草稿）
```

**只用项目规范**

```text
按 nichespate/docs/Style.md 去 AI 味，不要强行加个性。
```

**更新个人档案**

```text
voice-update：从这篇终稿更新 VOICE.md
（贴终稿或给路径）
```

## 12. 明确不做

- 不为「更像人」伪造实验细节或引用  
- 不用名人作者腔或营销号 voices 覆盖个人 VOICE（除非用户点名要玩票）  
- 不把 SaaS humanizer / 过检测当验收  
- 不在 clean 稿上为了显得勤快而大改  
- 不把 Style 与 VOICE 冲突时擅自各打五十大板——按 §2 优先级
